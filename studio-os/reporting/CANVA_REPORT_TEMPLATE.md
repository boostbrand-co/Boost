Canva design: `BOOST® REPORT TEMPLATE`

## Purpose

This Canva design is the canonical visual shell for BOOST recurring client performance reports.

It contains three reference pages:

1. **Page 1 — Cover**
2. **Page 2 — Standard interior-slide chrome / shell**
3. **Page 3 — Back cover**

These pages define fixed BOOST presentation behavior. They are not inspiration to reinterpret every month.

## Page 1 — Canonical cover

Use page 1 as the fixed reporting-cover structure.

Preserve:

- BOOST visual hierarchy
- B® identifier placement
- black / near-black left field
- narrow orange BOOST rule
- right-side period panel
- typography scale and spacing logic
- metadata positions
- overall proportions

Only update approved dynamic fields such as:

- client name
- period
- month label
- year
- client-specific dark accent / panel treatment when approved

Do not redesign the cover for each client.
Do not add photography unless Ana explicitly approves it for that report.
Do not stretch or distort any logo or image.

## Page 2 — Standard interior-slide chrome

Page 2 is the reference for how a normal report slide should carry BOOST identity.

Treat it as **presentation chrome**, not as a rigid content layout.

Preserve the recurring BOOST identifiers and spacing behavior shown on this page, especially:

- B® placement
- top-of-slide report / client metadata treatment
- footer / pagination behavior when present
- safe margins
- relationship between BOOST identity and the client content area

The body of each slide remains modular. Charts, tables, thumbnails, diagrams, KPI blocks and strategic reads may use different layout families from the Reporting Design System.

Do not force every interior slide to use the same composition as page 2. Use page 2 to standardize the frame around the content.

## Page 3 — Canonical back cover

Use page 3 as the fixed BOOST reporting close.

Preserve:

- BOOST identity
- black / near-black treatment
- spacing and hierarchy
- minimal close behavior

Update only the report-specific closing copy when needed.

The close should stay concise. It should not become another strategic-summary slide.

## Canva finalization workflow

When Canva access is available, the final report should be assembled from this canonical shell rather than manually repaired by Ana.

Preferred flow:

1. Create or import the approved report body.
2. Make a copy of `BOOST® REPORT TEMPLATE`; never overwrite the master.
3. Keep page 1 as the first page.
4. Use page 2 as the visual reference for interior-slide chrome while preserving the report body's modular layouts.
5. Insert all approved report-body slides after the cover.
6. Keep page 3 as the final page.
7. Update dynamic cover / closing fields.
8. Run Canva-specific QA.
9. Rename the final design using the BOOST naming convention.
10. Return the editable Canva link to Ana.

## Naming convention

Use:

`BOOST® <CLIENT DISPLAY NAME> Reporte <PERIOD LABEL>`

Examples:

- `BOOST® AB Taller Reporte Julio-Agosto`
- `BOOST® Ramiro Cárdenas Reporte Agosto`

Do not add version labels such as `V2`, `V3`, `FINAL`, `Claude`, or `Generated` unless Ana explicitly requests them.

## Canva QA

Before delivery verify:

- cover is page 1
- back cover is last
- client name is correct
- period / month / year are correct
- report title follows naming convention
- B® and metadata treatment match the canonical template
- interior-slide chrome is consistent
- no imported page is missing or duplicated
- no text overflows
- no chart labels shifted during import
- no image or logo is stretched
- no internal QA / source notes appear client-facing

If Canva import damages a slide, correct it before delivery when feasible.

## Governing rule

The BOOST reporting system should generate the **content and analysis modularly**, then finish inside the **fixed BOOST Canva shell**.

The cover, interior identity chrome and back cover should become more consistent over time, not get redesigned by AI every month.
