# BOOST Report Editorial Compression

Status: V1 working standard  
Owner: BOOST  
Applies to: client-facing recurring performance reports and monthly review decks.

## Purpose

BOOST reports should feel strategic and substantial without reading like documents pasted into slides.

The goal is **high useful density with low verbal drag**.

A client should understand the point of a slide in a few seconds, then choose whether to read the supporting detail.

## 1. Title system

Use a three-level hierarchy only when needed:

1. **Eyebrow** — short section label, usually 1–4 words.
2. **Headline** — the slide's main title, usually 3–7 words.
3. **Optional subhead** — one short sentence only when the headline cannot carry enough context.

Do not use a full analytical conclusion as the headline when that makes the title two lines long.

Prefer:

- `ANUNCIOS` / `Apoyo y conversaciones`
- `FACEBOOK` / `Crecimiento sostenido`
- `INSTAGRAM` / `Recuperar el ritmo`
- `CONTENIDO` / `Lo que sí conecta`
- `PLAN ESTUDIANTE` / `Siguiente prueba`
- `PRÓXIMOS MOVIMIENTOS`

Over:

- `Instagram cerró el periodo arriba; agosto bajó de ritmo con menos continuidad de publicación`
- `Facebook creció en visibilidad y en acción: 31% más vistas, 67% más clics`

The data and subhead can carry the supporting explanation.

### Title targets

Use these as editorial targets, not hard character-validation rules:

- eyebrow: 1–4 words
- headline: 3–7 words
- headline usually under ~45 characters
- optional subhead: one line when possible

If the title reads like body copy, shorten it.

## 2. One slide, one conclusion

Every core slide should have one dominant job.

The slide may contain several metrics, but they should support one conclusion.

If a slide needs two separate paragraphs to explain two different ideas, either remove one idea or split the slide.

Do not create a slide whose only job is to restate the previous slide in strategic language.

## 3. Insight compression

Client-facing insight blocks should be concise.

### `LECTURA BOOST`

Default: one sentence.

Target: roughly 15–30 words.

It should answer:

`What does this evidence mean?`

Do not repeat all the numbers already visible above it.

### `DECISIÓN`

Default: one sentence.

Target: roughly 10–25 words.

It should answer:

`What changes next?`

Implementation detail belongs in speaker notes, appendix or internal analysis unless the client needs it to approve the direction.

### Bullets

Prefer one line per bullet.

If a bullet contains two semicolons, several commas and a second sentence, it probably needs compression.

## 4. Executive-summary density

The executive summary should not become a memo.

Use:

- 3–5 hero metrics,
- 2–4 short progress bullets,
- 1–3 next-period focus bullets,
- one short overall read only if it adds something.

Avoid four-line bullets.

The summary should be skimmable in under one minute.

## 5. Synthesis discipline

Do not stack several learning / synthesis slides in the core deck.

If the deck already has:

- an executive summary,
- slide-level `LECTURA BOOST` blocks,
- content-learning slides,
- a next-moves slide,

then a separate `LECTURA ESTRATÉGICA` slide is often redundant.

Keep a dedicated cross-channel synthesis slide only if it produces a genuinely new conclusion that cannot live clearly elsewhere.

Likewise, `EN OBSERVACIÓN` should usually remain internal unless the client needs to know the signal now.

### Default preference

For most reports:

`Executive Summary → Evidence / Platform Slides → Content / Priority Initiative → Next Moves → Appendix → Close`

This is a narrative preference, not a rigid slide template.

## 6. Positive framing without extra prose

Constructive language should not make slides longer.

Improve framing through:

- order of information,
- proportional emphasis,
- calmer vocabulary,
- shorter context,
- a clear next action.

Do not add three explanatory sentences to soften one decline.

Prefer:

`Instagram cerró arriba en el acumulado; agosto bajó de ritmo con menos continuidad. Recuperaremos la cadencia antes de cambiar la estrategia.`

Over a multi-sentence paragraph explaining why the client should not worry.

## 7. Text budget by slide type

These are design targets, not hard caps.

### Metric / chart slide

- headline + optional subhead
- 3–6 supporting metrics
- one chart
- one insight sentence

### Content evidence slide

- headline
- 1–5 visible creative examples depending on size
- short labels / metrics
- one learning sentence

### Strategic-priority slide

- headline
- evidence
- one short read
- one short decision

### Next-moves slide

Prefer 3–4 actions.

Each action should be readable as:

`ACTION — short reason — success measure if needed`

Avoid mini-paragraphs under every column.

## 8. Remove before shrinking

Never solve density by shrinking body copy below comfortable laptop reading size.

Edit in this order:

1. remove repetition,
2. remove low-priority metrics,
3. shorten wording,
4. move technical detail to notes / appendix,
5. combine redundant synthesis slides,
6. only then reconsider layout.

Do not preserve every sentence and reduce font size.

## 9. Thumbnail test

At thumbnail size, the viewer should be able to distinguish:

- what the slide is about,
- the hero number / chart / content artifact,
- whether it is evidence, learning or action.

If every slide looks like a title followed by several text boxes, the editorial system has failed.

## 10. Final editorial QA

Before export, ask:

- Is any headline a full sentence that could become a shorter title + subhead?
- Is the same learning expressed on more than one dedicated slide?
- Does any `LECTURA BOOST` exceed what a client needs to understand the point?
- Does any `DECISIÓN` contain implementation detail the client does not need?
- Can one sentence replace a paragraph without losing accuracy?
- Did positive framing add words instead of improving proportion?
- Are we keeping a strategic-read or watchlist slide only because the template expects one?
- Could the client skim the core deck in a few minutes and still understand the story?

A report is editorially finished when the thinking remains deep but the reading feels light.
