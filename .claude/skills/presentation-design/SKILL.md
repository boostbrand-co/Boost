# Presentation Design

Create presentations that feel strategically structured, visually rich, intentional, and fully art-directed.

This is the permanent quality standard for presentations across BOOST projects. It is brand-agnostic. Apply the active project's real identity, audience, objective, and source material. Never default to the look of a previous client or presentation.

The standard is not “clean slides.” The standard is a presentation that explains the idea clearly, makes the audience picture it, controls attention, and moves people toward the intended outcome.

The deck should feel designed, not formatted.

## 1. Start with the job of the presentation

Before making slides, define:

- audience
- purpose
- desired decision, belief, or action
- what the audience already knows
- what they need to understand
- likely objections or confusion
- available evidence
- emotional outcome
- factual constraints
- presentation context: live, sent as PDF, workshop, pitch, report, or leave-behind

Build the narrative around that job.

Different presentations require different logic. Examples:

### Client proposal
Context → problem → opportunity → approach → scope → proof → timeline → investment → next step

### Brand strategy
Context → research → audience → insight → positioning → verbal identity → visual direction → applications → decisions

### Audit / research presentation
Executive finding → evidence → implications → priorities → recommendations → action plan

### Sales presentation
Situation → pain → desired outcome → solution → proof → offer → objections → next step

### Investor presentation
Problem → timing → thesis → solution → business model → market → GTM → proof → team → economics → ask

### Internal / leadership presentation
Decision required → current state → evidence → options → recommendation → execution plan

Do not force a generic slide order. Build the story the material needs.

## 2. Every slide needs a strategic job

Before designing a slide, define:

- **Strategic job:** what must this slide accomplish?
- **Audience question:** what does it answer?
- **Desired takeaway:** what should the viewer remember?
- **Visual hero:** what should dominate visually?

No slide exists because “this information is useful.” Every slide must advance understanding, conviction, or action.

If two consecutive slides do the same job, combine them.

If a slide contains two unrelated jobs, split it.

## 3. One dominant idea per slide

The viewer should know what matters before reading the body copy.

Choose one visual hero:

- large number
- photograph
- product mockup
- diagram
- process flow
- map
- chart
- timeline
- comparison
- case-study metric
- quote or insight
- portrait / capability
- framework
- before-and-after
- artifact or screenshot

Supporting content should reinforce the hero.

Do not make five elements equally loud.

## 4. Premium does not mean empty

Whitespace must frame an idea. It must not look like unused canvas.

If a slide feels sparse, do not solve it by adding paragraphs. Add useful visual information:

- diagrams
- charts
- maps
- timelines
- UI fragments
- proof artifacts
- photography
- image crops
- structured grids
- architecture
- annotations
- nodes and connections
- comparison systems
- labels and data tracks

Increase **visual density**, not text density.

A slide should feel complete from edge to edge even when it contains very little copy.

## 5. Use multiple layout families

Never build an entire presentation from one repeated template.

Use recurring layout families appropriate to the project:

### A. Cinematic / narrative
Large photography, restrained copy, strong composition.
Use for openings, section breaks, emotional moments, future-state visualization, and closes.

### B. Data / evidence
Large metric, clean chart, supporting proof.
Use for research, performance, market data, validation, results, benchmarks.

### C. Product / system
Interfaces, workflows, diagrams, maps, process logic.
Use for solution, experience, systems, methodology, service delivery.

### D. Human / credibility
Portraits, capability maps, testimonials, case studies, team, customer stories.

### E. Framework / strategy
Matrices, ladders, spectrums, maps, prioritization, architecture, decision trees.

Consistency comes from the design system, not from repeating the same composition.

## 6. Build visual rhythm across the deck

The thumbnail view should already feel designed.

Use the active brand palette to alternate visual environments such as:

- dark / high-emphasis
- light / analytical
- secondary brand-color / transition
- photographic
- product-heavy
- data-heavy

Do not produce ten consecutive slides with the same background and structure.

Do not alternate mechanically either. Let narrative intensity determine the rhythm.

## 7. Photography must explain or dramatize the idea

Photography should not decorate a slide. It should help the audience imagine the customer, behavior, environment, product, result, or future state.

Useful photographic jobs:

- show the customer in context
- show the product or service being used
- show a before / after state
- make an abstract strategy tangible
- visualize the environment where the business lives
- create an emotional pause between dense sections
- make the audience picture themselves in the outcome
- show branded applications realistically

Avoid generic visual filler:

- staged handshakes
- smiling-at-camera stock
- generic laptop photos
- irrelevant skylines
- empty luxury interiors without strategic meaning
- AI-looking people
- repeated scenes
- decorative stock that adds no information

For image generation, produce **individual high-quality images only**. Never combine multiple requested images into a collage unless the user explicitly asks for a collage.

When applying branding in mockups, use the exact supplied logo. Never invent, simplify, redraw, or replace the mark.

## 8. Use photographic interstitials intentionally

A photo + short phrase slide can strengthen a presentation when it helps the audience absorb or picture an idea.

Use sparingly. These are not filler slides.

Good reasons to use an interstitial:

- create a pause after dense evidence
- turn an abstract insight into a visible scene
- mark a new chapter
- reinforce the central thesis
- show the desired future state
- make the audience feel the customer experience

In a live presentation, these can be 5–10 second moments.

## 9. Product and service visuals should feel tangible

If the project has a digital product, show the interface at useful scale.

Use:

- browser mockups
- desktop + mobile combinations
- workflow states
- dashboards
- filters
- search states
- forms
- reports
- before-and-after views

If the project is a service, visualize the service:

- workflow
- deliverables
- journey
- team interaction
- artifacts
- process map
- sample output

Do not shrink real work into tiny decorative screenshots.

Do not invent unsupported product capabilities, metrics, deliverables, or functionality.

## 10. Diagrams must encode real logic

Use diagrams when relationships matter more than prose.

Useful types:

- process flow
- funnel
- flywheel
- lifecycle
- decision tree
- system architecture
- category map
- comparison matrix
- prioritization matrix
- customer journey
- timeline
- two-lane roadmap
- money in → outcome out
- cause → effect chain

Do not add decorative arrows around text blocks. The diagram must clarify how something works.

## 11. Charts must be presentation-grade

A chart should answer one question.

Use:

- direct labels
- clear units
- limited series
- meaningful annotations
- restrained gridlines
- intentional scaling
- strong hierarchy

Avoid:

- 3D charts
- decorative pies
- unnecessary legends
- tiny labels
- excessive ticks
- spreadsheet screenshots when a clean chart can communicate the point

If the chart needs a paragraph to explain it, simplify the chart or add one explicit insight beside it.

## 12. Text should be edited for presentation, not pasted from documents

Slides are not pages.

Convert source material into:

- headlines that carry the argument
- short supporting sentences
- labels
- proof points
- visual structures

Do not paste long prose into a presentation and reduce font size until it fits.

Move depth into:

- speaker notes
- appendix
- leave-behind version
- supporting document

## 13. Writing standard: professional, direct, human

Use Hardik Pandya's Stop Slop principles as a prose-quality filter while keeping the language appropriate to the audience.

Do:

- state the point directly
- use active voice
- name the actor
- use specific nouns and verbs
- use numbers where they clarify
- preserve precise domain language
- vary sentence length
- keep complete sentences when context matters

Avoid:

- throat-clearing
- generic AI language
- filler
- forced rhetorical questions
- formulaic “not X, but Y” reversals
- dramatic fragments
- empty adverbs
- “unlock / reimagine / revolutionize / game-changing / world-class / frictionless”
- slogans used in place of explanation

Headlines should communicate a useful idea, not sound engineered for a quote card.

## 14. Evidence discipline is non-negotiable

Never invent:

- metrics
- clients
- testimonials
- quotes
- credentials
- dates
- partnerships
- product capabilities
- case-study attribution
- financial performance

Distinguish clearly between:

- verified/current
- underway
- planned
- target
- modeled
- illustrative
- estimated

Do not make the slide design imply more certainty than the source supports.

## 15. Case studies should prove something

A case study slide must answer: why does this result matter here?

Use the strongest commercially or strategically relevant proof:

- revenue
- ROAS
- leads
- sales
- orders
- cost per lead
- conversion
- scale
- adoption
- efficiency
- qualitative transformation

Prefer one hero result and one supporting proof point.

Do not turn case studies into dense mini reports.

## 16. Team and people slides should show capability

Avoid résumé walls.

For each person, prioritize:

- role
- capability
- relevant experience
- standout proof

Use consistent portrait treatment.

Keep secondary people visually secondary.

## 17. Branding should be present without becoming wallpaper

Use the active project's brand system.

Respect:

- exact logo
- color palette
- typography
- iconography
- photography direction
- visual motifs
- brand personality

Useful patterns:

- full logo on cover, close, and key brand moments
- icon-only mark on interior slides when appropriate
- brand-colored rules, nodes, labels, or data accents
- recurring visual motif used with restraint

Do not paste the full logo loudly onto every slide.

Do not reuse another project's color system or visual style unless explicitly requested.

## 18. Live presentation vs leave-behind

When needed, create two depths.

### Live presentation
- tighter
- larger visuals
- fewer ideas per slide
- faster pacing
- easier to speak over

### Leave-behind / reading deck
- more context
- supporting detail
- appendix
- additional evidence

Same narrative, different density.

Do not create a live deck by shrinking a leave-behind deck.

## 19. Appendix is a design tool

Use the appendix to protect the clarity of the core story.

Possible appendix content:

- detailed research
- source notes
- methodology
- extended financials
- additional cases
- full scope
- channel detail
- long bios
- technical detail
- supporting data
- FAQs

The main deck should remain focused.

## 20. Presentation workflow

### Step 1 — Audit source material
Identify the source of truth, contradictions, missing proof, and unsupported claims.

### Step 2 — Define the presentation job
Audience, desired action, objections, context.

### Step 3 — Build narrative architecture
Write the slide sequence before designing.

### Step 4 — Define pacing
Mark where the deck should explain, prove, pause, inspire, compare, and conclude.

### Step 5 — Assign a strategic job and visual hero to every slide
No orphan slides.

### Step 6 — Choose layout family for each slide
Avoid repetition.

### Step 7 — Design / build
Do not stop at a written description when the user asked for the presentation.

### Step 8 — Review as thumbnails
Check rhythm, color balance, density, repetition, and pacing.

### Step 9 — Review slide by slide
Check hierarchy, image crop, spacing, alignment, type size, chart quality, and copy length.

### Step 10 — Final content QA
Verify facts, names, figures, dates, labels, roles, and any pending items.

## 21. Acceptance checklist

Before calling a presentation finished, ask:

- Does the opening establish the point quickly?
- Does every slide have a strategic job?
- Does every slide have a visual hero?
- Is any slide only headline + columns of text?
- Is there meaningless empty space?
- Is visual density high without clutter?
- Are different layout families used?
- Does the thumbnail view have rhythm?
- Are dark/light/photo/brand-color moments balanced?
- Are product or service visuals large enough to feel real?
- Does photography illustrate the idea?
- Do diagrams encode actual logic?
- Are charts understandable at laptop size?
- Is evidence visually distinct from targets or illustrative content?
- Are case studies relevant to the story?
- Are team slides capability-led?
- Has repeated content been combined?
- Is the core presentation tight enough for its use case?
- Does the close leave the audience with the intended belief or action?

If several answers are no, the deck is not finished.

## 22. Quality bar

The final presentation should feel:

- intentional
- premium
- visual
- clear
- intelligent
- persuasive
- specific
- evidence-led
- human
- fully art-directed

It should never feel like:

- a generic AI deck
- a repeated template
- a wall of text
- a set of empty minimalist slides
- a document pasted into slide software
- a spreadsheet disguised as a presentation

The goal is not to make slides look nice. The goal is to make the audience understand the idea, picture it, trust it, remember it, and respond the way the presentation was designed to make them respond.
