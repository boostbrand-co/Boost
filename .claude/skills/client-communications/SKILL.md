# Client Communications

Use this skill for client-facing messages, follow-ups, approvals, updates, boundary-setting, feedback responses, scheduling, and next-step coordination.

## Principle

The message should move the work forward while preserving trust.

Do not sound like customer support, a formal memo, or generated relationship-management copy unless the situation requires it.

## 1. Start from the action

Identify what the message needs to achieve:

- get a decision
- get missing information
- confirm scope
- update progress
- explain a recommendation
- ask for feedback
- schedule a meeting
- reset expectations
- follow up
- protect boundaries

Write toward that action.

## 2. Match the channel

### Slack / WhatsApp
- short
- conversational
- direct
- minimal greeting/sign-off

### Email
- clearer structure
- complete context
- explicit next step

### Formal client / legal-adjacent
- precise wording
- less casual tone
- document decisions and dates

## 3. Do not repeat the client

Avoid starting by paraphrasing everything the client just said.

Acknowledge briefly when useful, then add value.

Good:
“Agreed. I’ll combine those two slides and keep the visual concept from 6.”

Weak:
“Thanks for sharing that you think slides 4, 6, and 8 could be combined…”

## 4. Recommendations

When giving advice:

- state the recommendation
- give the reason
- explain the tradeoff only if it matters
- suggest the next action

Do not over-defend the recommendation.

## 5. Disagreement

Disagree without making the client defend their idea.

Useful structure:

- acknowledge the intent
- name the risk
- propose a better use / placement

Example:
“The Airbnb comparison is useful shorthand. I’d keep it secondary rather than use it as the category definition, because our model differs on transaction and control.”

## 6. Questions

Ask only questions that materially unblock the work.

Bundle related questions when the client can answer quickly.

Use clear answer formats when useful:

- A / B
- confirm / change
- short-answer list

## 7. Boundaries and scope

Be specific.

State:

- what is included
- what changed
- what requires a new decision / scope
- what can happen next

Avoid vague “this is outside scope” language without explaining the operational consequence.

## 8. Progress updates

A useful update answers:

- what is done
- what changed
- what is blocked
- what happens next

Do not send activity logs unless requested.

## 9. Natural voice

Use contractions when appropriate.

Avoid:

- “kindly”
- “I hope this message finds you well”
- “please be advised”
- fake enthusiasm
- repetitive thank-yous
- over-apologizing
- emojis in formal contexts

Follow the client relationship and the user’s actual voice.

## 10. Apply Stop Slop 2

Always apply `stop-slop-2` in Message Mode.

Especially avoid:

- repeating the recipient’s words
- filler openings
- formulaic empathy
- long justification
- vague action language

`stop-slop-2` owns the universal anti-AI writing rules and the channel-specific Message Mode. This skill adds client-relationship, scope, recommendation, and boundary logic.

## Acceptance checklist

- Does the message have one clear purpose?
- Is the ask / next step obvious?
- Is the tone right for the channel and relationship?
- Did it add information rather than repeat?
- Is the message shorter than it needs to be?
- Does it preserve confidence without sounding rigid?

If not, revise.
