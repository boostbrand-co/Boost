# Design System Direction

Use this skill when translating strategy into a visual system for websites, products, presentations, social content, campaigns, and brand applications.

## Principle

A design system is not a moodboard with colors and fonts. It is a set of repeatable visual decisions that make different outputs feel related while staying useful for their context.

The system should feel designed, not templated.

## 1. Start from strategy

Review:

- brand category
- positioning
- audience jobs
- brand personality
- tone
- business objective
- product truth
- desired perception
- competitive visual conventions

The visual direction should reinforce the business idea, not decorate it.

## 2. Audit references correctly

For each reference, identify what is useful:

- layout intelligence
- spacing
- hierarchy
- image treatment
- typography relationship
- motion
- interface density
- grid
- color behavior
- data visualization
- editorial rhythm

Do not copy another brand’s logo, colors, typography, icons, assets, or signature composition unless explicitly licensed and requested.

Extract principles, not surfaces.

## 3. Define the visual thesis

Write one sentence describing how the brand should feel visually and why.

Then define:

- what it should resemble
- what it should avoid resembling
- what visual tension makes it distinctive

## 4. Color system

Define roles, not only hex codes:

- primary / structural color
- action / signal color
- secondary accent
- neutral backgrounds
- text hierarchy
- status colors
- data-series use

Use accent colors as signals, not wallpaper.

Build a deliberate dark/light/brand-color rhythm across multi-page experiences.

## 5. Typography system

Define:

- display family / role
- body family / role
- scale
- weights
- line heights
- label style
- numeric style
- data / table style
- capitalization rules

Typography hierarchy must work at actual output sizes, not only in a type specimen.

## 6. Layout and grid

Define:

- base grid
- max content widths
- spacing scale
- section rhythm
- card logic
- image ratios
- alignment rules
- breakpoint behavior

Avoid repeating one composition across every screen or asset.

Consistency should come from the system, not identical layouts.

## 7. Photography direction

Photography must illustrate the business or customer experience.

Define:

- subject
- environment
- lighting
- crop
- level of polish
- human presence
- realism
- negative-space behavior
- what to avoid

When generating images:

- produce individual assets unless a collage is explicitly requested
- use the exact supplied logo for brand application
- never invent or reinterpret logos
- avoid obvious AI artifacts and generic stock behavior

## 8. Graphic language

Define reusable motifs that encode meaning:

- lines
- nodes
- frames
- dividers
- shapes
- map/grid logic
- tags
- labels
- data tracks
- texture
- icon family

Every graphic device should organize information or reinforce the brand idea.

## 9. UI / product translation

For digital products define:

- navigation behavior
- cards
- lists
- filters
- forms
- empty states
- status chips
- buttons
- modal/sheet behavior
- tables
- search
- data density

Do not let the system become a visual demo that hides product usability.

## 10. Presentation translation

When the system is used in decks, apply `presentation-design`.

Preserve:

- color rhythm
- typography hierarchy
- image world
- visual motifs
- chart language
- iconography

Do not turn the presentation into the website squeezed onto slides.

## 11. Social / campaign translation

Create flexible content families, not one template repeated forever.

Define 3–6 repeatable compositions:

- editorial statement
- data / proof
- photography-led
- product / artifact
- quote / testimonial
- campaign concept

## 12. Motion

Use motion to clarify state, sequence, hierarchy, or continuity.

Avoid movement that exists only to look impressive.

Define:

- transition speed
- entrance behavior
- scroll behavior
- shared-element logic
- hover behavior
- reduced-motion fallback

## 13. Build from real situations

Do not approve a system only from logo, palette, and mockups.

Test it on real outputs:

- homepage hero
- detail page
- mobile state
- form
- presentation slide
- social post
- data visualization
- email / document cover

A system is credible when it survives actual content.

## Acceptance checklist

- Does the visual system express the strategy?
- Can it create variety without losing recognition?
- Are colors assigned roles?
- Does typography work at real sizes?
- Is photography specific to the business?
- Are motifs meaningful rather than decorative?
- Does the system work across web, deck, and social use cases?
- Does it avoid looking like a copied reference?
- Does the output feel premium without becoming empty or overdesigned?

If not, iterate.
